## The code

```al
L.Init();
L."Report ID" := Report::"Standard Sales - Invoice";
L.Name := 'LT W5 Own Stream';
L."Layout Format" := L."Layout Format"::Word;
Report.WordLayout(Report::"Standard Sales - Invoice", InS);
L.Layout.ImportStream(InS, 'the report''s own word layout');
L.Insert();
```

The default Word layout of report 1306 "Standard Sales - Invoice" has an external relationship in
`word/_rels/settings.xml.rels`: an `attachedTemplate` that points to a local `.dotx` file.

## What changed

- **29.1:** the insert fails with
  `Errors were detected in the Word layout: UnsupportedExternalContentFields: The Word layout contains unsupported fields or external references: ExternalRelationship:attachedTemplate`.
- **27.5 and 28.5:** the insert fails too. The probe asserts the start of the text (`Errors were detected in the Word
  layout:`) and the error code `ReportLayoutValidation:WordLayoutValidation`.
- **29.0:** the insert works and the row is stored.

The layout file is the same in 29.0 and 29.1 (same MD5 in the Base Application source). The validation in the
service tier changed.

## Who is affected

Code or test libraries that copy a Microsoft report's Word layout into Tenant Report Layout, and custom Word layouts
that were saved from a template on disk. Such layouts worked on 29.0 and fail on 29.1. Remove the attached template
from the document before you import it.

## Microsoft documentation

Yes, in general terms. [KB 5135161](https://support.microsoft.com/help/5135161), platform hotfix 654475: "Handles
external references in Office documents for layout and mail merge." It does not say that such layouts are refused.
The what's new page for update 29.1 does not mention it.
