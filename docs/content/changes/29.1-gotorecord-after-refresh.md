## The code

A Worksheet shows rows with `MarkedOnly`. A tile's OnDrillDown marks rows 1 and 2 and calls `CurrPage.Update(false)`.
Then code outside the page clears the flag of row 2 and sets a "refresh done" flag in a SingleInstance codeunit. The
page's next OnAfterGetCurrRecord consumes that flag, marks only the flagged rows again (row 1) and calls
`CurrPage.Update(false)`. The test then calls `GoToRecord` for row 2, without calling `First` before it.

## What changed

- **27.5, 28.5 and 29.0:** `GoToRecord` of row 2 returns `false` and row 1 stays current. The marks were already
  re-applied when `GoToRecord` ran.
- **29.1:** `GoToRecord` of row 2 returns `true` and row 2 becomes current. The TestPage still sees the old marks.

The probe asserts more observations after this one (whether the refresh flag was consumed, a second `GoToRecord`).
CI reports only the first observation that differs, so those later results on 29.1 are not measured yet.

This may come from the same platform change as the
[page part refresh sequence](../29.1-page-part-refresh/). That is not confirmed.

## Who is affected

Tests that call `GoToRecord` on a page that changes its marks or filters in OnAfterGetCurrRecord, right after code
outside the page changed the data.
